## 当前性能复测

沿用交付包的三个完整分钟热点，每个输入 1,200 根 5 分钟 bar × 100 个证券。
固定规则、费用、资金、目标和五类单线程设置；每个版本／场景使用新进程和独立空 Numba 缓存，
正常启用 GC，至少三轮、累计十秒暖态采样。主计时为完整 `Backtest.run` 返回，包含全部立即物化
记录；字段哈希及实际 C 调用探针在计时之外核验。全部输入及 26 个结果字段与正式基线相等，
仅来源的实现哈希不同。Linux 计时前后生产源码和原生二进制哈希一致。

| 场景 | Windows 0.5.0 / 纯包+Numba 秒 | Linux 0.5.0 / 纯包+Numba / 原生+Numba 秒 |
| --- | --- | --- |
| 密集股数目标 | 4.010 / 0.568 | 3.898 / 0.798 / 0.355 |
| T+1／限价／状态 | 5.669 / 0.323 | 3.419 / 0.543 / 0.277 |
| 开盘权重重平衡 | 7.673 / 0.838 | 6.786 / 1.005 / 0.375 |

Windows 三行暖态加速为 7.06／17.54／9.16 倍；Linux 原生相对正式 0.5.0 为
10.98／12.34／18.11 倍。Linux 原生使用本次 sdist 构建并实际安装的 wheel，
三行均独立观察到四次 C 物化调用。Windows 不加载该扩展，提升来自数组运行时和编译循环。

代价是首次 JIT 与内存：Windows 三行首次 run 从 11.27／9.67／12.21 秒变为
14.83／15.09／16.10 秒；输入准备另计。Linux 进程峰值（包含导入、输入准备、首次 JIT
和暖态结果，在校验哈希前采样）为：

| 场景 | 0.5.0 MiB | 纯包+Numba MiB | 原生+Numba MiB |
| --- | --- | --- | --- |
| 密集股数目标 | 405.0 | 608.6 | 726.6 |
| T+1／限价／状态 | 346.0 | 504.3 | 569.5 |
| 开盘权重重平衡 | 451.4 | 659.2 | 804.6 |

这不是降低内存或改善所有冷启动的优化。Windows 此次只复测耗时和字段，未另外采样峰值内存。
Linux 是本机 WSL 环境，两个系统的绝对耗时不能交叉计算加速倍数。
原始样本、输入／输出摘要、版本和计时记录保留在本地 `.quality/native-integration-*-performance`；
复测脚本保留在 `.quality/benchmark-native-integration.py`。

原交付中的 17/17 VectorBT 暖态结论属于其原 Linux 环境和限定矩阵；本次没有重新测量
VectorBT，不将其当作当前机器、默认 Python 后端或任意策略的统一性能保证。

本机 Windows 与 WSL 共用源码目录。首次 Linux 完整测试为 915 通过、2 失败，失败位置为
策略源码哈希：函数缓存中的 `co_filename` 指向 Windows 路径，Linux 的 `inspect.getsource`
无法读取。改用 Linux 独立 `PYTHONPYCACHEPREFIX` 和 `NUMBA_CACHE_DIR` 后，受影响的
`test_provenance.py` 12 项通过；保留首次失败日志，不修改断言或生产代码来消除失败。
最终 Linux 检查在隔离缓存中重跑，两系统不共用编译缓存。
