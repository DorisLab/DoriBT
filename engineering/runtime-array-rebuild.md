# 通用运行时数组重构

本记录对应 2026-10-12 的第三轮优化；前两轮记录保留在
[运行时优化记录](runtime-optimization.md)。目标是扩大受益范围，而非继续只优化
无公司行动的日线股数目标。性能结论必须由同一输入、相同输出工作量的独立进程实测支持。

## 架构

- `Account` 以可增长整数数组保存交易批次，按证券维护 FIFO 链，按可卖日维护交收事件堆。
  证券查询返回副本；非单调交易日查询针对当前存活批次重新计算，不返回历史持仓。
- `ArrayBroker` 在一次数值调用中推进全部活动委托，共享现金、冻结量、成交量参与上限，
  稳定地先卖后买。订单数值数组和成交缓冲区保留完整记录，回调读取与最终结果仍物化
  为原有不可变公开对象。普通 Python 后端保留参考经纪路径。
- Numba 下的分钟 `PositionTargets` 与完整规则区间的 `WeightTargets` 使用整个数值循环，
  复用同一订单队列和账户批次内核。权重支持收盘／开盘定量及显式重新平衡；数量不是
  根据未来成交反推。实际成本、最低佣金、部分成交、T+N、状态、限价及滑点仍生效。
- 含公司行动和任意 Python 策略保留 Python 生命周期边界，但共享数组经纪与账户，
  不要求把回调改写为 JIT 函数。税务按日末净变化单独管理批次，不使用成交碎片替代。
- 权益账本按到期事件处理到账和送转，税务只扫描相应证券和未结清税款；事件记录
  顺序、应收款、待入账股份、欠税与后续缴税仍完整保存。
- 回调账户视图通过不可变数组快照按需生成 `Position`，避免每个 bar 为所有证券
  提前创建对象。保存的旧上下文不会看到后续成交；映射查询、迭代、`copy()` 与映射合并保持兼容。
- 已验证数值行批量提取元数据，再完整物化原来的冻结 dataclass 类型。私有记录工厂
  更新每个新实例的独立字典以保留共享键布局；公开构造器、字段顺序、类型和记录协议
  不变，遇到不适用的类型或初始化器回退到原构造器，不使用延迟审计来缩短计时。

审计缓冲区按实际事件几何扩容，不为稀疏策略预留所有 bar×证券的最坏订单数。
每根 bar 的现金／持仓／可卖／冻结／权益数组仍按公开结果契约完整保存。

## 不变条件与边界

公开调用仍是 `MarketData → Backtest.run → BacktestResult`；没有新增必装依赖，没有
修改许可证，没有复制 VectorBT 代码。借鉴的是数组状态、事件调度、编译循环的通用思想。
VectorBT 的代码许可证与 DoriBT 的 Apache-2.0 不能因此混同。

无活动规则的权重区间继续走完整回调路径，保留原错误时点；有公司行动的预计算策略
仍由权益生命周期驱动，并使用数组经纪撮合。旧式日线执行模式继续保留。
来源记录中的 `execution_path` 是历史逻辑入口标签，不是全部内部 JIT 细节。

任意 Python 回调本身可能任意耗时，不能承诺对所有可能策略和输入都低于 VectorBT
三倍。比较必须区分相同语义的实现与功能不对等：尤其不能用静态订单回放冒充动态
账户回调，也不能删掉公司行动、税务、冻结和审计输出后宣称全场景达标。

## 验证要求

- 原始基线独立进程对比全部结果字段，来源只允许实现哈希改变
- 编译／参考经纪、预计算／逐 bar 回调、同一策略强制回退逐字段比较
- 独立整数／Decimal 账本，包含共享资金、部分成交、订单累计最低佣金、T+0/T+N
- 留存上下文首次延迟访问、多次运行隔离、超过初始缓冲容量的扩容与冻结一致性
- 公司行动事件顺序、税务 FIFO、回调异常链和权重定量错误时点
- 冷启动、数据准备、预热执行、相同输出物化、回调正文及峰值内存分别报告
- Python／Numba 完整本地门禁、两类隔离 wheel、文档和依赖／凭据审计

最终广覆盖矩阵包含 18 行；全部结果字段与独立基线一致，run_info 只改变实现哈希。
17 行有共同经济语义对照，其中 14 行在三倍以内；密集分钟股数、分钟 T+1／限价／
状态、分钟执行时权重重平衡仍分别为 4.24／4.44／5.16 倍。公司行动没有外部等价模型。
因此全场景目标尚未完成；不能隐去三个失败项或以延迟审计替代原计时契约。

两个密集负载的数值执行约 0.06 秒，完整原生构造约 0.56／0.86 秒，主要时间花在
数万到十余万原类型冻结记录上。这是实测热点，不是理论下界。原生批量物化等后续
实验应单独记录；可选数组结果也只能作为经批准的新工作流，不能冒充旧输出达标。
完整测试、独立回归与明确未解决项见[发布进展](release-progress.md)。
