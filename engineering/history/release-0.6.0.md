# 0.6.0 发布验收

本版合入已核验的四个性能交付提交，并修复代码审计发现的全部问题。用户明确要求不创建 PR，
采用当前 `codex/integrate-native-records` 分支完成验证后快进合入 main，再发布新版本。
既有 0.5.0 标签和发行包保持原样。原始交付来源见[合入复核](../native-records-integration.md)。

## 改动与审计闭环

| 审计项 | 最终改动与验证 |
| --- | --- |
| date.max 覆盖溢出 | 使用整数排他边界，仍接受闭区间；覆盖与未受影响证券均有独立预期 |
| 旧结果零冻结数组可写 | 两个派生零数组只读，导出不再能被直接赋值改写；数值保持原样 |
| 每分钟重复规则转换 | 按证券与交易日查规则，复用相同不可变规则的数值参数；成交量逐 bar 读取 |
| Context 反复线性找证券 | PreparedData 的只读列索引跨 Context／持仓视图复用，保持原证券顺序 |
| 导出构造全量字典列表 | CSV／JSON 流式写出和分块哈希，保留字节、列序、全部记录与原子不覆盖语义 |
| 原生重复／空表时间轴转换 | 空表直接返回，稀疏下标访问原始时间轴，密集转换按次共享 |
| 编译路径重复账户数组 | 分配账户前选择执行计划；编译循环拥有结果，OHLC 历史按需准备 |
| 日线最坏审计容量 | 四类缓冲几何扩容，保留完整记录、FIFO 和消费后的编号 |
| 隐式七数组账本协议 | LedgerState 集中分配／扩容，Account 持有当前引用，内核使用具名字段 |
| C 逐字段临时引用与可读性 | exact list／tuple 借用引用，分离校验和构造，保留 GIL／稳定 ABI 与错误清理 |
| 缓存工厂绕过新构造器 | 每条轻量检查 __init__／__new__ 身份，Python 路径调用更换后的构造器；原生拒绝不稳定类型 |

没有新增公共执行选项或策略接口。任意回调、自定义目标子类、公司行动和非活动权重输入的
生命周期／错误时点保持原路径；预计算只针对精确内置目标类型及已声明的适用条件。

## 容量与测量口径

同一冻结 3000 日×500 证券、100 股恒定目标、零费用／滑点、T+0 交收、收盘决策／次日开盘执行输入，
直接对比 b5 与本版解释内核，八个输出逐项精确相等。实际订单、意图、税务批次与成交各 500 行。
四类审计底层 ndarray 容量从 **275,932,000 字节降至 184,000 字节**。这是审计缓冲容量，
不等于完整回测内存或整进程 RSS；逐 bar 账户矩阵、高换手记录及 JIT 内存仍需保留。

1200×100 导出样例的 Python 分配峰值由约 40.43 MB 降至 0.174 MB，positions.csv 的
3,720,091 字节及 SHA-256 完全一致。这是 writer 的 tracemalloc 测量，不代表完整导出 RSS 或运行速度。
96×100 准备微基准十次中位数 58.92→9.99 ms，编译数组精确相等；局部结果不代表所有回测。

完整热点的冷／暖耗时、阶段内存以及 GitHub／PyPI／Pages 发布证据将在实际完成后补充。
