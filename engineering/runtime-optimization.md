# 完整账本运行时优化

基线为 0.5.0 的 d655b3ca016616dcc3bc84c0e6030317096c7f48。本轮目标是保留现有
成交、账本、审计输出和公开调用方式，缩小预计算目标策略与 VectorBT 的完整运行差距。
未增加轻量结果模式，未禁用验证、费用、税务、公司行动或日界线处理。

## 第一轮实现边界（c900868；通用回退路径保留）

- 精确内置 `PositionTargets` 使用已归一化的目标直接提交变更意图，仍经过同一
  `BarIntentBook`、Broker、账户和日终生命周期；参数签名与行情对齐验证仍在入口执行。
  子类、任意回调和 `WeightTargets` 继续使用 Context。异常继续附带策略收盘时点。
- 账户维护证券列索引、注册总数和按交收日查询的缓存。返回数组仍为独立副本；非单调
  日索引查询、T+1/T+2 和送股挂牌前的可卖约束均保留。新批次必须走 `add_lot`，卖出必须
  走 FIFO `_sell`；不可绕过这些内部入口直接改写 `lots`。
- 冻结资金和冻结股份通过单一 `_reservations` 入口增量更新。申报、部分成交、重新冻结、
  撤销、到期和期末处理都走此入口；同一证券多张委托仍共享冻结约束。
- 内部订单用可变 `OrderState` 保存，外部读取时生成缓存的不可变 `Order` 快照。
  每次变动标记对应订单索引；已经交给用户的快照不会随后改变。结果仍完整物化全部订单、
  意图和成交，字段和顺序不变。
- 日末税务批次仍按证券输入顺序及每日净持仓变化处理，保留与交易 FIFO 分离的税务账本。
  只对发生过批次变动的证券核对；无应税收入的卖出不重复计算持有期税率，但日期检查仍在。
- 估值与买单冻结估值增加共用公式的 Python/Numba 数值内核，乘法前检查金额上限。
  日循环、订单生命周期和公司行动仍由 Python 驱动，不能称为全引擎编译。
- 纯 Python `int` 的输入换算改用精确整数乘法及同样的上下界检查，避免反复转为 Decimal。
  bool、整数子类、NumPy 标量、浮点、Decimal 和字符串保留原解析路径。

## 验证与测量

最终验证、各轮原始时间和复现命令见随补丁交付的性能核验报告与原始 JSON。
运行时计时包含公开 `Backtest.run`、全部最终审计记录及共同输出提取；准备与首次调用
分别报告。没有修改原基准脚本和人工行情生成方式，也没有将未计时工作移入隐藏缓存。

代表性负载为 2,520 日 × 100 证券单组合，以及 100 个不同 SMA 参数组合 × 同一行情的
独立共享现金账户。VectorBT 每次批处理十个独立组合，DoriBT 复用准备行情逐组合运行；
保留原比较协议，不把不同的分组方式误称为相同内部执行。

这些人工无摩擦负载的性能结论不覆盖所有策略、所有规则或其他机器。正确性另以完整
回归、独立 A 股案例及全部公开结果字段对比核验，不能由速度或 Python/Numba 相同
单独推出金融语义正确。账户信息准备、首次编译和公司行动复杂负载仍可能有额外开销。

## 2026-10-12 本地计时结果

同一台 Linux / Python 3.13.5 环境，NumPy 2.5.4、Numba 0.68.0、VectorBT 与
vectorbt-rust 1.1.2。三个串行配对试验，每个单组合进程先运行一次，再测七次；
每个网格进程只预热第一个组合，再完整运行 100 个不同组合一次。
BLAS、OMP、Numba、Rayon 均限制为一个线程，垃圾回收维持默认启用状态。

| 指标 | DoriBT Numba | VectorBT Rust | DoriBT / VectorBT |
|---|---:|---:|---:|
| 单组合，21 次暖态中位数 | 0.6035 秒 | 0.08568 秒 | 7.04 倍 |
| 单组合，全部暖态范围 | 0.5278–0.7659 秒 | 0.07317–0.10996 秒 | 不混配极值 |
| 100 组合，3 次中位数 | 60.7286 秒 | 6.7207 秒 | 9.04 倍 |
| 100 组合，全部范围 | 59.8533–62.6945 秒 | 6.6516–6.8275 秒 | 配对 8.89–9.43 倍 |

与修改前同协议已有记录相比，DoriBT 单组合 3.3392→0.6035 秒（5.53 倍提速），
100 组合 314.8626→60.7286 秒（5.18 倍提速）。修改前记录与本轮不同时运行，不把这个
提速估计当作受控实验的置信区间。网格准备时间从修改前 55.58 秒降到本轮 9.35–9.76 秒。

全部 100 组合共 1,393,518 笔成交，每次试验的逐 bar 现金、持仓、权益及全部成交都与
同一独立整数参考一致。单组合为 15,824 笔成交。

原先较快的 VectorBT 参考值 0.0815 秒／6.1844 秒对应本轮 DoriBT 中位数 7.41 倍／
9.82 倍；本轮网格最慢一次超过旧固定 61.84 秒阈值，但三个同轮配对都低于 10 倍。
这说明目标在报告的暖态代表负载中达到，并非任意机器、任意运行或任意策略的性能保证。

准备和首次执行未隐藏：DoriBT 单组合准备 6.51–6.83 秒、首次执行 5.29–5.39 秒；
VectorBT 分别 1.17–1.45 秒、0.30–0.35 秒。首次执行包含输入编译与其他首次使用工作，
不能称为纯 JIT 编译时间，也不能将暖态的低于 10 倍结论延伸到独立的首次执行阶段。

## 第二轮：日线股数目标编译循环

在第一轮基础上，将无公司行动的日线内置 PositionTargets + BarExecution + Numba
推进为整段数值循环。参考 VectorBT 的数组状态与编译控制流组织方式，但复用 DoriBT
的整数撮合、费用、滑点、冻结估值和估值公式，保留原有 A 股账户契约。没有复制对方的
浮点账户或特定 SMA 策略逻辑，没有修改公共基准脚本。

- 明确入口条件，不匹配则保持原路径。包括公司行动的普通日线和所有分钟数据仍由
  原 Broker / Account / RightsBook 处理，不声称这些负载也获得同样提速。
- 编译循环覆盖每日意图排序、前一收盘申报与资金冻结、卖出优先的执行、部分成交、
  DAY 到期、T+N 释放、独立税务 FIFO、逐 bar 估值，以及完整数字审计记录。
- 所有公开订单、成交、意图和税务批次在 Backtest.run 返回前完整物化，未改变结果
  类型或字段。来源 JSON 将配置片段一次合并，避免解析并再次序列化整个目标矩阵；
  数据、目标、配置、参数、版本和源码来源仍完整保留。
- 新增完整结果差分、独立边界预期、精确回退与重复运行隔离核验。两类 wheel 安装
  额外实际执行无公司行动的日线股数目标，核对账本与审计记录。
- 编译记录缓冲按日数 × 目标证券数预分配；减少动态对象调度，但可能增加临时内存。
  首次编译耗时与暖态分开测量，不把额外准备移出原计时边界。

第二轮三个串行配对试验：单组合 21 次暖态中位数 0.14038 秒，VectorBT Rust
0.07796 秒，差距 1.80 倍；100 参数完整网格中位数 18.1443 秒，VectorBT Rust
6.6007 秒，差距 2.75 倍。三次网格配对分别 2.727／2.790／2.833 倍，均低于三倍。
相对第一轮再提速 4.30 倍／3.35 倍；历史跨轮比值不作为受控实验的置信区间。

单组合全部暖态范围 0.1262–0.4043 秒，网格 18.0024–19.4192 秒；没有排除高延迟
样本。低于三倍是暖态中位数及本轮完整网格配对结论，不是每一次调用的延迟保证。
新缓存首次执行 12.219 秒（含行情准备和编译），VectorBT Rust 0.459 秒；后续新进程
使用磁盘缓存时仍为 4.810–4.828 秒。冷启动没有达到三倍以内。完整网格准备为
9.792–9.901 秒，进程峰值 RSS 约 2.115–2.117 GiB；这些成本均未隐藏。

全部三轮逐 bar 现金／持仓／权益及成交与独立整数参考一致，每轮完整网格包括
1,393,518 笔成交。最终门禁和全部结果字段对比另附原始核验记录；第一轮时间保留
为历史证据。远程 GitHub 写权限仍未恢复，本轮依然只有本地交付。
