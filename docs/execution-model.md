# 当前共享账户执行契约

本文定义 0.1.0 正式 API 的多标的账户、收盘策略、目标权重、开盘执行及分红送转记账。权益与普通个人股息税的适用范围见[权益模型](corporate-actions.md)，发布验收各项证据见[首版验收](release-0.1.0.md)。

## 研究入口

`Backtest(data, initial_cash=..., costs=Costs(...)).run(strategy, parameters=..., backend="python")` 接受收盘函数，也接受 `WeightTargets`。策略函数获得 `Context`，无需继承类；显式 `parameters` 会复制后作为关键字参数传给函数，初始值进入运行记录。普通函数工厂和可调用对象也可使用，但其闭包和内部状态不会自动收集。每次 `run` 都建立独立账户，有自身状态的策略对象须由用户为各次运行重新创建。

- `ctx.history(symbol, bars=..., field="close", adjustment="raw")` 返回截至当前收盘的只读价格副本，默认原始 OHLC；可显式选择 `adjustment="asof"`，仅使用当前已除权且已知的事件因子，详见[研究价格视图](data-contract.md#按决策时点复权的研究视图)。当前窗口不足时返回已有历史。此接口防止无意读取未来数据，不是对恶意 Python 代码的沙箱。
- `ctx.account` 提供元为单位的现金、可买现金、分红应收、税款应付、权益及不可变持仓／可卖量；`Position.quantity` 是已入账股份，`pending_quantity` 是待入账股份，`value` 包含二者的估值。`ctx.orders`、`ctx.intents` 提供截至当前的记录。
- `ctx.order(symbol, quantity)` 提交有符号股数，仅尝试下一输入交易日；负数卖出。数量不合法会留下拒绝记录，不默默凑整。
- `ctx.target_positions({symbol: quantity})` 持续尝试达到绝对股数，省略证券保持原目标。新目标替换同证券旧目标，记录取消原因。
- `ctx.target_weights(weights, rebalance=False)` 设置整个组合的目标权重，省略证券为零。权重变化时按当前收盘权益和价格确定股数，按当期规则向合法数量取整；相同权重继续原股数目标，不每天再平衡。显式 `rebalance=True` 每次重算。
- `ctx.cancel(intent_id)` 取消仍活动的意图。回调结束后不能再通过保存的 Context 改订单。
- `ctx.bar_index` 为输入日历从零开始的序号，包含停牌交易日。按输入交易日间隔调仓可直接计数，不假定自然周或交易所节假日。

预计算 `WeightTargets` 日期必须与行情逐项一致，权重非负、总和不超过一。它调用同一收盘入口，默认同样只在权重变化时重算。输入被保存为不可变值；不自动丢行、重排或前填。自动延迟执行不能证明用户因子没有前视。

## 每日顺序与共同现金

开盘先处理除权、到期股息、股份入账和前日已计提税款，再按当日可卖批次生成上一收盘意图的委托，以当日开盘和配置滑点执行；先卖后买，同侧按 `MarketData.symbols` 的声明顺序处理。卖出所得可以用于后续买入，但须为未清税款留出资金。收盘按净股份变化更新税务批次、计提税款，再捕获当日登记权益，估值后调用策略。每个证券同一时点只有一个活动意图，多次提交会按替换规则留痕。

权重委托的股数在收盘确定。下一开盘跳空不重新按开盘权益配比，资金不足时减至能支付费用的合法股数；原目标保留未完成部分，下日重试。单次股数委托的剩余量当日到期，不自动重试。原预算模型已从开发版移除，不作为正式接口。

规则包含单笔数量上限时，单次股数委托越限会拒绝；持续目标按上限每天至多生成一张子委托，分日完成。买入拆分会为后续保留可满足最小买入量的余额；目标只有达到整体股数才完成，不因其中一张子委托成交而提前结束。权重减仓不会发出低于卖出最小量的部分减持；清仓仍保留零股例外。预设范围及数量假设见[市场规则](china-market.md)。

送转除权时，尚未完成的持仓目标按送转比例调整至整数股，调整前后值与事件 ID 保存在 `intent.adjustments`；固定股数单次委托不改写。目标差额包含待入账股份，避免把尚未到账误当缺仓；这些股份仍不能提前卖出。现金分红不自动改变股数目标。

买入批次按买入日规则确定交收交易日，周末不当作一个交易日。卖出只消耗已解锁 FIFO 批次。当前模拟没有盘中回调，即使数据声明 T+0，也不因此产生当天收盘下单、当天开盘卖出的穿越行为。

## 委托、成交与费用

`result.intents` 是目标和有效期，`result.orders` 是当日尝试，`result.fills` 是实际成交，分别带 ID 并可追溯关联。委托事件包括创建、接受、成交／部分成交、拒绝／到期；部分成交后剩余部分当日到期。替换和用户撤销记录在持续意图上。样本结束仍未执行的意图标记 `end_of_data`，不暗中强平。

日线模型每个证券每日只模拟一个成交片段，因此最低佣金按该日委托收取一次，分项记录佣金、印花税和过户费；不是每笔内部资金试算都收费。费用按分半入，账本使用整数万分之一元，金额溢出直接失败。佣金是否包含其他券商规费由用户配置决定，当前仅显式另计印花税和过户费。

`Order` 和 `Fill` 的 `commission`、`stamp_duty`、`transfer_fee` 直接返回元；对应 `_units` 字段保留精确整数记账值，分析费用无需手动猜单位。

现金在顺序撮合过程中立即占用并记账，未成交委托当日到期；收盘视图的冻结现金为零，没有跨日冻结订单。可买现金为现金扣除应付税款后与零的较大值，股息应收不能用于买入。当前未提供取款接口或银行结算模拟，不能把收盘现金解释为已核验的可提现额度。

## 日线成交假设

停牌、未上市／已退市、零成交量、买入开盘触及涨停、卖出开盘触及跌停均不成交并记录原因。价差滑点按证券 tick 计，超过已知日价格边界时不成交。不使用当天最终最高／最低价裁剪开盘价格，不读取当日收盘价反算开盘数量。

零成交量阻止成交属于整根日线的历史模拟约束。当前不按日成交量比例设置数量上限，也不模拟盘口排队或集合竞价撮合；有成交量不意味着真实市场可以无冲击执行任意数量。库存按收盘原始价估值，持仓进入无估值的退市状态直接失败，不能以零价格清空。

## 后端及结果边界

Numba 加速同一个整数开盘执行循环；生命周期、批次和任意 Python 策略回调仍在 Python 层。预计算目标也走此流程，当前不承诺整个账户按一次 JIT 批量编译，更不能引用原单标的原型的速度作为本引擎成绩。

结果包含一维权益／现金／分红应收／税款应付、按证券命名的持仓／可卖量／待入账股份矩阵、全部意图／委托／成交、权益事件／税务记录、数据指纹、税务政策版本和实际后端。整数金额字段以万分之一元用于精确复核；元为单位的属性用于研究。收益从本次初始现金算起，回撤峰值包含初始现金。`stats()["dividend_tax"]` 汇总已计提税款（含未支付），与成交费用分开。完整风险指标、基准、图表、导出和策略来源记录见[结果说明](results.md)。
