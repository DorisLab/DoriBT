# 质量检查

本文规定维护者的开发检查。新增能力须连同有独立预期的行为验证交付，CI 结果以对应提交的实际运行状态为准。

## 本地入口

Python 3.13，安装 [uv](https://docs.astral.sh/uv/)。检查锁定依赖，不在检查期间更新版本。

```sh
# 基础安装：不需要 Numba；隔离 wheel 检查还会确认没有安装它。
uv sync --locked
uv run --no-sync python scripts/check.py

# 完整后端检查与联网依赖审计。
uv sync --locked --extra numba
uv run --no-sync python scripts/check.py --backend numba --audit
```

`check.py` 任一步失败即返回失败；使用独立临时目录构建，防止误测 `dist/` 中的旧 wheel。安装检查使用锁定的运行依赖，在仓库之外以 `python -I` 执行，不能借用源码目录的可编辑安装。Numba 检查要求依赖实际存在，不能因缺依赖跳过。开发依赖包含 Matplotlib，以便两个任务都验证图表和静态类型；隔离的基础 wheel 环境明确不安装 Matplotlib／Numba，并检验缺依赖错误。Numba wheel 环境同时安装 `plot` extra，实际导出 PNG／CSV／JSON，验证每个文件的哈希。

凭据扫描由 CI 的 Gitleaks 检查执行，固定 CLI 8.30.1 并核对下载文件 SHA-256。本地安装 [Gitleaks](https://github.com/gitleaks/gitleaks) 后，`gitleaks git --redact` 检查历史；将本次文件加入暂存区后，`git diff --cached --binary | gitleaks stdin --redact` 检查待提交内容，注意尚未暂存的新文件不在此命令范围内。扫描器报告若涉及凭据只展示脱敏信息，不把真实密钥写入错误样例或报告。

## 门禁内容

| 检查 | 阻止的问题 |
| --- | --- |
| `uv lock --check` | 配置与锁文件不同步 |
| Ruff 检查／格式 | 未使用与错误符号、易错模式、NumPy API 迁移及格式差异 |
| 文件大小／复杂度 | `src`、`tests`、`examples`、`scripts` 下每个 Python 文件不超过 400 物理行（含空行、注释），每个函数 McCabe 复杂度不超过 10；不设历史豁免 |
| mypy strict | 库、示例和检查脚本的类型契约错误；仅 Numba 无类型存根的导入边界单独声明 |
| pytest 严格配置／告警 | 未知标记、未处理告警和回归失败 |
| 手算与独立 Decimal | 成交、费用舍入、现金、持仓、权益错误；不以 Python/JIT 相同作为独立证明 |
| Hypothesis 生成式账本 | 不同价格、费用、预算、停牌及独立账户组合下的数值和资金不变量 |
| 时间与失败路径 | 信号错误对齐、同日执行、未来输入影响过去、缺 Numba 静默回退、非法数据和溢出继续运行 |
| 文档与安装 | README 示例过期，wheel 缺类型标记／许可证，基础安装误依赖 Numba，安装包行为与源码不同 |
| pip-audit | 锁定的运行依赖（包含全部 extras）存在已知漏洞；查询失败同样失败，不伪报安全 |
| Gitleaks | 提交中包含凭据特征；扫描不替代数据再分发授权审查 |

覆盖率包含分支并列出遗漏位置，用于找缺失行为；当前不以一个百分比代替关键案例，也不为凑数字添加同义测试。生成式测试采用固定的可复现配置并由 Hypothesis 缩减失败输入；独立预期使用 Decimal，不能导入内核的计费或记账函数计算答案。

引擎 CI 为 Windows／Linux × Python基础安装／Numba安装四个检查组合，另有依赖审计与凭据扫描。`milestone/**`（排除 `milestone/docs/**`）直接运行；`v*` 由发布工作流复用同一套门禁，通过后构建并上传 PyPI。`milestone/docs/**` 与正式 GitHub Release 的 published 事件仅触发文档构建、教程验证及 Pages 发布。引擎里程碑可手动触发；普通提交、分支 push 和 PR 更新均不触发。工作流固定 Action 提交，默认只读，仅部署 job 获得对应发布权限。

文档入口：`uv sync --locked --group docs` 后运行 `uv run --no-sync python scripts/check_docs.py`。它严格构建 Sphinx、检查生成页面的内部链接／锚点／资源，将示例复制到临时目录执行，并验证教程正文的 Python 片段。`--python <path>` 可改用从 PyPI 安装的独立环境，`--backend numba` 验证可选后端。文档构建依赖不进入运行依赖。

## 迭代与新增能力

日常迭代先跑受影响用例，例如 `uv run --no-sync python -m pytest tests/test_minute_execution.py -m 'not numba'`；代码稳定后再跑完整入口。基础任务会明确排除标为 `numba` 的用例，对应 Numba CI 任务必须执行这些用例，不使用 `importorskip` 隐藏依赖问题。

后续能力需要的最小验证包括：

- 订单和账户：成交重建现金与持仓，拒绝／部分完成／撤销／到期及目标替代路径。
- 多标的：共享资金、卖出后买入、稳定排序、参数账户隔离，证券顺序变化的政策说明。
- 市场规则：交易日交收、数量约束、规则有效日期／缺口、停复牌和未知状态。
- 公司行动：登记、除权、应收、到账、可卖日与税费的独立账本，避免复权与现金重复计入。
- 指标和导出：手算收益／回撤／费用，基准与年化口径，文件读回和来源信息齐全。

结果门禁覆盖四段手算收益、独立基准协方差与跟踪误差、零分母／单样本／零风险、实际参数驱动的成交、导出文件独立账户重建；发布前写入失败、文件损坏和其他进程抢先创建同名目标时须保留既有文件。Windows／Linux 使用各自的原子不替换操作，不能以 POSIX 可覆盖空目录的普通 `rename` 冒充该保证。图表测试检查渲染和曲线值，代表性图表仍须实际查看。

性能比较先核对结果与输出相同，再分别记录冷启动、预热后耗时和内存。公共 CI 不用一个易受机器负载影响的毫秒阈值决定财务正确性。建立代表性完整引擎基线后再制定性能退化门槛。

`scripts/benchmark.py` 在两个独立进程、全新 Numba 缓存中运行单标的、参数网格和共享资金组合；逐项核对输出摘要后才发布报告。`psutil` 仅为开发依赖，采样包含 Windows 虚拟环境启动器的子进程。CI 运行小规模功能检查，不以速度排名决定通过；完整测量方法与结果见[性能基线](../engineering/history/performance.md)。

失败不能通过删断言、提高账本误差容忍度或增加广泛忽略来解决。必要例外须说明原因、受影响范围、替代证据和复查期限；当前没有依赖漏洞或告警豁免。

分钟新增门禁包括独立 Decimal 成交／账户重建、佣金累计、冻结／释放、T+1 与日内权益边界、缺分钟／时区错位失败、时间因果与导出。基础与 Numba wheel 安装检查都实际执行分钟多次成交。`benchmarks/` 同样纳入 400 行、复杂度、格式及 strict mypy；vectorbt 是隔离比较环境依赖，不进入 DoriBT 运行依赖。比较脚本中的浮点核对仅为 vectorbt 运算舍入容差，DoriBT 与 Decimal 仍逐单位精确相等。

滑点边界门禁覆盖 strict／cap／cost 与三种模型的高点买入、低点卖出，区分原始涨跌停成交阻断与滑点越界；用户限价、非正价格、冻结现金、部分成交与累计佣金须有独立预期。两个后端、预计算／回调、日线／分钟及隔离 wheel 都验证边界选择；成交参考价和运行配置须可从导出读回，滑点成本不得重复扣除。

目标与资金门禁覆盖跳空后的固定股数、其他挂单冻结保护、未占用现金补充、含费用的明确支出上限、部分成交残差，以及收盘／开盘定量的手算预期。开盘定量须在所有成交前按统一权益计算，纳入待入账股份及应收分红，不能使用同 bar 收盘价；取消、替换、模式切换、最后一根未定量意图和来源导出均须可核对。预计算扫描不能漏掉原冻结额不足、但空闲资金足够的成交。公开 target_sizing 示例和两类隔离 wheel 验证同一契约。

预计算分段执行须与逐 bar 路径核对所有结果数组及意图／订单／成交／权益／税务记录，不只核对最终收益；两种 wheel 实际运行 PositionTargets。来源缓存须保持规范 JSON，并在替换行情、费用或依赖版本后反映新事实。性能样本中的分钟／日线成交量差异可作为来源元数据保留，不因此截断效率测试区间；两种引擎必须读取同一份分钟输入。

参数与研究输出的定向入口为 test_research_parameters／test_research_outputs／test_research_report：费用必须真实改变成交资金并按订单累计最低值，参数错误必须在首次回调前失败，自定义输出不得覆盖已有 namespace 或在失败时留下半份导出。日频报告必须纳入首日费用、按日末采样分钟结果、明确基准对齐；交易盈亏以手算移动成本及独立 Decimal 公司行动账本验证。两种隔离 wheel 实际运行 RunConfig、声明参数、record、自定义指标和 daily 导出，验证源码分目录后依赖及公开导入完整。
