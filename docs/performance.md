# DoriBT 性能测试与复现

在 **2,520 日 × 100 标的、预计算持仓目标**的合成组合中，DoriBT 纯包搭配 Numba 的
热运行中位数为 **0.147 秒**，VectorBT Rust 为 **0.075 秒**，耗时比约 **1.95×**。
默认 Python 后端为 **0.970 秒**。这些数字适合判断重复研究时的执行成本，首次运行还须计算
输入准备和 JIT 编译。

本页整理已保存的实测证据，不把文档更新视作重新跑分。结果对应的精确安装包、依赖、产物哈希、
逐轮数据和合成脚本保存在[公开复现材料](https://github.com/DorisLab/DoriBT/tree/main/engineering/benchmarks/documentation-20261013)中。
性能取决于输入规模、成交密度、策略接口及结果需求，不构成任意策略的速度保证。

## 先区分三种配置

- **默认纯包 + Python**：基础安装即可运行，是未显式选择后端时的配置。
- **纯包 + Numba**：另外安装 Numba，运行时显式选择 `backend="numba"`；不含 C 审计记录扩展。
- **自行构建原生包 + Numba**：在 Numba 之外启用可选 C 记录物化器；本次仅验证了
  **Linux x86_64、CPython 3.13、启用 GIL**。它不是默认安装产物，也不是所有执行路径都会使用的加速器。

安装与后端选择见[安装指南](guide/install.md)，可选原生范围见[原生记录](native-records.md)。

## 日线主对照：2,520 日 × 100 标的

所有配置使用相同 seed、OHLC、5/20 日 SMA 信号和 1,000 万初始现金；目标持仓为每标的
0 或 100 股，收盘生成目标，下一根 bar 开盘成交，共 **15,824 笔成交**。
这是 **XNYS 日历上的无摩擦合成负载**：关闭费用、T+1、涨跌停和公司行动。
它衡量通用执行效率，不用于证明 A 股规则真实性。

计时包含公开引擎调用及现金、持仓、权益、逐笔成交的输出提取。每个热轮均核验全部经济输出，
不是仅比较期末收益。每配置至少 3 次热运行，累计热计时至少 10 秒。

| 配置 | 输入准备含引擎导入（秒） | 新缓存首次执行（秒） | 热运行中位（秒） |
| --- | ---: | ---: | ---: |
| DoriBT 纯包 + Python，预计算目标 | 6.634 | 3.907 | 0.970395 |
| DoriBT 纯包 + Numba，预计算目标 | 6.649 | 13.112 | 0.146962 |
| DoriBT 自行构建原生包 + Numba，预计算目标 | 6.487 | 12.414 | 0.140649 |
| DoriBT 纯包 + Python，目标包装回调 | 6.603 | 3.635 | 0.983619 |
| DoriBT 纯包 + Numba，目标包装回调 | 6.564 | 8.226 | 0.713335 |
| VectorBT Numba，预计算目标 | 1.213 | 12.301 | 0.095528 |
| VectorBT Rust，预计算目标 | 1.233 | 0.481 | 0.075334 |
| Backtrader | 0.092 | 18.051 | 18.964515 |
| Zipline-reloaded | 1.319 | 6.807 | 7.151099 |

纯包 + Numba 的准备与首次执行合计约 **19.76 秒**，尚不包含共同的行情和 SMA 生成。
**0.147 秒不是首次端到端耗时**。输入准备、编译、重复执行和输出工作应按自己的研究流程分别评估。

此日线预计算路径实际进入 `CompiledRun/daily_targets`，**没有调用 C 审计物化器**。
原生包与纯包的几毫秒差异不能归因为 C 加速。公开的 `run_info.execution_path` 是较粗的接口标签，
实际内部路径已用计时外的独立诊断确认。

## 放大研究工作量：100 个独立组合

**100 组 SMA 参数 × 每组 100 标的 × 2,520 日**，合计 **2,520 万个标的-bar**。
每组是独立共享资金账户，每次完整扫描产生 **1,393,518 笔成交**，100 个账户的全部经济输出均通过核验。

| 配置 | 独立进程数 | 执行中位数（秒） | 最小–最大（秒） |
| --- | ---: | ---: | ---: |
| DoriBT 纯包 + Numba | 3 | 19.131 | 18.670–19.808 |
| DoriBT 自行构建原生包 + Numba | 3 | 20.036 | 18.577–20.204 |
| VectorBT Numba | 3 | 7.677 | 7.388–9.138 |
| VectorBT Rust | 3 | 6.744 | 6.523–7.034 |
| DoriBT 纯包 + Python | 1 | 93.563（单次观察） | 不作区间推断 |

纯包 + Numba 与 VectorBT Rust 的中位数之比约 **2.84×**，三轮配对比值为 **2.72–2.94×**。
原生包的中位数之比约 **2.97×**，但有一轮达到 **3.10×**，不能说每轮都在 3 倍以内。

这是两种公开工作流的比较：DoriBT 串行执行 100 次公共 API，VectorBT 每批原生处理 10 个共享资金组合。
信号、独立参考和输入准备在计时外，完整结果提取在计时内。两边预热工作量不同，预热时长不能用于冷启动排名。
各进程使用新缓存，三轮按交替顺序配对；Backtrader、Zipline 没有运行此规模，不将未运行写成超时。

### 小批量也可能更慢

另一个 **10 组单标的 × 2,520 日独立账户**的工作流中，纯包 + Numba 为 **0.062993 秒**，
VectorBT Rust 原生 10 列批处理为 **0.016860 秒**，耗时比 **3.74×**。
默认 Python 为 0.476256 秒。规模变小不会自动使固定开销消失。

应收、支付、税批次与延迟送股的外部等价模型，**不报告跨框架速度比**。

### 对照工作流决定结论

四个目标回调主对照保留双方 Python 回调；它们并非相同 API，也不等于各框架能实现的最优工作流。
预计算目标使用 VectorBT Rust，共享资金、费用、部分成交、权重和状态约束使用相应 Numba 适配；
有状态订单主对照使用 Python flexible callback。

额外测试将目标回调改为 VectorBT Rust 预计算、将有状态订单手工改写为 Numba 后：

- 原生包 + Numba 在分钟稀疏回调、日线密集回调、分钟密集回调中，相对 Rust 替代工作流分别为
  **3.14×、5.93×、9.26×**
- 纯包对应为 **3.23×、5.58×、9.31×**
- 有状态订单相对手工 Numba 改写，纯包为 **4.99×**，原生包为 **4.80×**

这些替代工作流保持经济结果等价，但不再保留同样的 Python 控制流成本。
因此“17/17 主对照”不能扩展为“所有策略、所有 VectorBT 写法都在 3 倍以内”。

## 正确性与计时口径

1. **经济输出**：通用日线和参数扫描每轮检查现金、持仓、权益及逐笔成交；矩阵的 56 份最终热轮
   经济输出另与独立整数参考核验。浮点比较只用于跨框架换算容差。
2. **完整审计**：矩阵 18 场景 × 2 安装的 36 份 DoriBT 公开经济／审计字段与冻结参考一致；
   来源元数据差异单独列出。公司行动仅作完整结果回归，不冒充独立外部模型验证。
3. **输出不完全同构**：DoriBT 保留更多原生审计对象，VectorBT 不生成所有对应字段；
   Zipline 还保留自身 metrics。经济等价不代表内部工作量完全相同。
4. **首轮单列**：矩阵在每个 DoriBT 批次开始时清空 Numba 缓存，同批后续进程可能复用它；
   不能把每一行首轮都叫作全冷 JIT。通用日线与大扫描则每个进程使用空缓存。
5. **重复与内存**：矩阵全部 58 个计时行至少 3 次、累计构造加输出至少 10 秒。
   进程峰值 RSS 包含导入、准备、参考模型和重复运行高水位，不作为纯引擎内存排名。

## 测试环境与复现

- Linux x86_64，AMD EPYC 9V74 80-Core Processor；性能窗口串行，无其他测试、编译或渲染竞争
- 通用环境：CPython 3.13.5、NumPy 2.5.4、Numba 0.68.0、pandas 3.0.6、
  VectorBT／vectorbt-rust 1.1.2、Backtrader 1.9.78.123
- Zipline-reloaded 3.1.1 单独使用 Python 3.12／pandas 2.3；按官方 slippage 扩展适配下一日开盘成交，
  日频事件时间戳仍为收盘，不混同两者
- OpenBLAS、OMP、MKL、Numba、Rayon 五项线程限制均为 1；不是 80 核并行跑分
