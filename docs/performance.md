# 完整引擎性能基线

2026-10-06，本地 Windows 11、AMD Ryzen 7 9800X3D（16 逻辑核）、Python 3.13.12、NumPy 2.5.3；可选 Numba 0.68.0／llvmlite 0.50.0。仅是这台机器上的观测，不是吞吐承诺。计时包含完整策略、订单、账户、权益生命周期和运行记录，不能与原型内核的数组循环时间直接比较。

## 工作负载与测量边界

- 单标的采用[市场案例](market-validation.md)的 159915.SZ、2020–2025 共 1455 个交易日。20／60 均线、95% 目标、初始 10 万元、佣金万三最低 5 元、1 tick 滑点；共 25 次成交。
- 100 组参数：快线 `5 + 2 × (i % 10)`，慢线 `40 + 5 × (i // 10)`，`i=0..99`。顺序调用同一 `Backtest.run`，每次独立账户；不并行，不把参数当成共享资金的证券列。
- 组合使用 20 个虚构 ETF、1455 个虚构交易日、固定随机种子 20261006。每 5 个输入交易日选择过去 20 日动量前 5 名、总权重 95%、初始 100 万元，共 1797 次成交。这是共享资金组合，不是 20 个独立账户。
- 两后端分别启动新进程、创建全新 `NUMBA_CACHE_DIR`。首跑包括行情准备、运行记录和首次 JIT；排除解释器／模块导入及 CSV 读取验证。CSV 读取验证另计，两后端均约 0.053 秒。
- 预热值为同一实例连续 5 次的中位数。参数批量为 100 次 `run` 耗时之和；结果摘要核对时间不计入。组合在单标的运行后测试，已预热开盘内核；组合首跑仍包含自己的行情准备。
- RSS 是外部每 5 毫秒采样的工作进程树之和，包含 Windows 虚拟环境启动器和真正的 Python 子进程，覆盖整个测量流程；可能漏掉短暂峰值，也可能重复计算共享页。计时与内存采样同时进行，采样器和其他本机负载会影响耗时。

## 实测结果

| 指标 | Python | Numba |
| --- | ---: | ---: |
| 单标的首跑（新进程／新缓存） | 0.144 s | 2.400 s |
| 单标的预热（5 次中位数） | 0.0583 s | 0.0586 s |
| 单标的 100 组参数 | 7.217 s | 8.152 s |
| 20 标的组合首跑（含组合行情准备） | 3.825 s | 4.117 s |
| 20 标的组合预热（5 次中位数） | 3.493 s | 3.766 s |
| 整个工作进程树的采样峰值 RSS | 86.6 MiB | 196.7 MiB |

Numba 在这批完整工作负载中没有明显收益。当前它只编译开盘执行循环；策略回调、历史查询、意图记录、账户／税务生命周期仍由 Python 管理。首版默认 Python，Numba 保持可选。不能据此推出所有策略或大规模参数研究都相同，也不宣称胜过 vectorbt 的专用数组路径。

重复运行复用不可变行情的编译结果与数据指纹，各次账户和订单仍独立；传入新的 `MarketData` 会重新准备，费用按本次配置编译。结果中的共享价格数组以只读字节为底层，不能通过修改写标志污染后续回测。`ctx.bar_index` 避免仅为定期调仓计数而复制整段历史。有状态策略对象仍须由调用者自行初始化。

## 结果核对与复现

每次预热、全部参数组以及组合逐一核对现金、权益、持仓与委托摘要，两后端必须一致才保存报告。真实 ETF 的均线摘要仍为 `efcc876042c737d520323b7bacadb8c9c3647f9800843c27b617227def857fdc`，与独立 Decimal 验收一致。

- 组合结果摘要：`d68ae8ab223599649d2527579a5d9ff94dd78bef04f3233a62dc770284e32b3b`。
- 全部工作负载合并核对摘要：`2ce27d6df64ee167aa3f14993c8fe101b01769ed54af86086cc68ec93b674c38`。
- 测量时引擎源文件摘要：`e67872dce3c65576925bfc958f40b5e3d3f8e7f91ac831877ef9667d7b8b0f1c`。

公开复现默认全人工数据，无须下载行情。输出文件须尚不存在：

```sh
uv sync --locked --extra numba
uv run --no-sync python scripts/benchmark.py --output benchmark.json
```

使用自己的真实 ETF CSV 时，增加 `--market`、`--calendar`、`--profile`、`--source` 与 `--no-corporate-actions`，输入和范围要求与市场验收工具相同。报告包含来源、参数、版本和结果摘要，不附原始行情。默认人工单标的与上表真实单标的不同，不能期待相同收益或耗时。内存采样依赖 `psutil`，仅装入开发环境，不进入引擎基础依赖。

CI 使用 60 日／2 标的／2 组参数检查工具确实启动两个后端、返回有效指标并拒绝不一致结果，不设置易受机器负载影响的毫秒门槛。后续性能工作应先观察意图历史和 Python 生命周期的成本，再决定编译边界；不能为速度省略账本或历史规则。
